# ADR-0001: Dynamic BMSTU profile identity and source gaps

## Status

Accepted for implementation.

## Context

The official catalog currently publishes duplicate direction-level profile codes, non-numeric suffixes and one combined direction label. The existing canonical contracts require valid direction/program ID shapes and unique program identities. Some linked study plans are empty directories or placeholders.

## Decision

Keep valid unique numeric profile codes unchanged. For a source profile whose code is not a valid unique canonical profile code, derive a deterministic numeric suffix from direction, raw source code, profile name and plan URL, probing collisions in stable sorted order. Preserve the original code in raw provenance. Add all valid direction codes from a combined source label; attach an otherwise ambiguous profile to the first source direction and emit a source-gap/quality record where disambiguation is not possible. Represent unavailable study plans as explicit source gaps while retaining the program and admissions data.

Extend the aggregate contracts additively with plural directions and source gaps. Keep the existing singular fields as compatibility aliases for current fixture/demo consumers. Persist gaps as raw audit records; do not create fake curricula.

## Consequences

- Existing `program:09.03.01-02` and `program:09.03.01-12` IDs remain stable.
- Canonical DB constraints remain valid without making API consumers accept arbitrary code syntax.
- New source profiles are deterministic and repeatable, but their derived suffix is an internal identity and must be explained in provenance/debug output.
- A full live snapshot can be useful even when its curriculum coverage is partial and explicitly reported.
