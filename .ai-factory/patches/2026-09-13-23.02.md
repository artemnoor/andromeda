# Exact module boundary allowlists

**Date:** 2026-09-13 23:02
**Files:** backend/tests/architecture/test_module_boundaries.py
**Severity:** low

## Problem

The architecture guard accepted an internal cross-module path when it merely
ended with `contracts.public` or `repository.ports`. A path such as
`andromeda.modules.disciplines.domain.foo.contracts.public` was therefore
treated as a valid public seam.

## Root Cause

The allowlist compared only the final two path segments instead of validating
the complete module contract path.

## Solution

The guard now accepts only the exact five-segment forms
`andromeda.modules.<module>.contracts.public` and
`andromeda.modules.<module>.repository.ports`. A regression assertion covers
the nested internal-path bypass.

## Prevention

- Validate architecture allowlists by exact structural paths.
- Add a negative regression case for nested names that share an allowed suffix.
- Keep relative-import resolution covered by the same boundary tests.
