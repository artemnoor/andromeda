# Long assistant suggestions on mobile

## Problem

The assistant page widened the mobile document by 14–36 CSS pixels. A long
predefined example question rendered as a single unwrapped button label, while
the header's own horizontal navigation was correctly scrollable.

## Root cause

The shared button style uses `white-space: nowrap`. The assistant suggestions
were placed in a wrapping flex container but had no maximum width or local text
wrapping, so the intrinsically wide button overflowed its card and the page.

## Solution

Constrained suggestion buttons to their container and enabled normal text
wrapping. Added a mobile Playwright regression that opens the assistant view,
scrolls the secondary navigation, and asserts that document scroll width never
exceeds the viewport. Confirmed the test failed at 426px document width before
the fix and passes at 412px after it.

## Prevention

- Include the actual assistant route in responsive tests; testing only the
  catalog home route misses assistant-specific content overflow.
- Assert the root document width against the viewport, not merely that the
  header itself can scroll horizontally.
- Keep long action labels wrapping inside cards on narrow screens.
