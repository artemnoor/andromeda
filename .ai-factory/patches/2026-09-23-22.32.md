# Explicit all-university admission scope

## Problem

After a user answered “Любые вузы”, the admission dialogue asked for university
scope again. The parser did not represent this answer, and the session derived
the missing scope solely from the absence of a named university. Merely
removing that question would have left the assistant without candidate
programs, while the existing batch request is intentionally limited to 50.

## Root cause

Conversation state had no typed value distinguishing “not answered” from an
explicit choice to search the full catalog. Candidate generation also sliced
university/direction results to the request batch size, which could silently
drop programs.

## Solution

Added a typed, explicit all-university scope fact and parser version update.
The assistant now selects the full relevant catalog, splits it into existing
50-program requests, and combines all results under a 5000-program safety
bound. The SQLAlchemy admission-fit reader uses bulk program/admission reads
instead of a per-program repository round trip. Added session, chunking,
service, and fixture-backed API regressions; regenerated OpenAPI and frontend
client contracts.

## Prevention

- Model explicit “all” choices separately from missing slots.
- Never satisfy an all-catalog query by truncating candidates to one batch.
- Keep transport request limits while evaluating large catalogs through a
  bounded bulk application path.
- Regression-test the complete clarification sequence through the API using
  canonical fixture data, as well as the pure state transition.
