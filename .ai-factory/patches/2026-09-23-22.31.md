# Responsive application navigation

## Problem

At common desktop widths, long secondary links shared one header row with the
primary navigation and account controls. The primary navigation could collapse
to zero width, leaving labels visually overlapping. Mobile navigation also
needs to remain independently horizontally scrollable without widening the
document.

## Root cause

The desktop layout revealed all secondary labels at an extra-wide breakpoint,
but did not reserve a separate row or minimum width for the primary navigation.

## Solution

Placed secondary desktop links in a second row and gave the primary navigation
the flexible space between the brand and account controls. Added a Playwright
geometry regression test at 1600, 1440, 1280, and 1024 pixels while preserving
the mobile overflow-scrolling navigation.

## Prevention

- Test navigation geometry at multiple desktop breakpoints, not only at the
  widest development viewport.
- Keep mobile secondary navigation in a bounded overflow container and verify
  that scrolling it does not create page-level horizontal overflow.
