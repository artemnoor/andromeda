# Render complete admission-fit outcomes in the assistant

## Problem

The assistant returned only “Проверено программ: N” after admission search,
even when each program outcome contained an insufficient-data status and a
source-backed explanation. Users could mistake a successful API call for a
positive admission assessment.

## Root cause

The web response formatter rendered analytics rows only and ignored the
structured `admission_result` data embedded in the neutral response envelope.
Its generic source note also did not distinguish incomplete admission data.

## Solution

Render up to five program codes with their typed Admission Fit status, optional
readiness score, and first data-gap explanation. The response now explicitly
warns that incomplete or ambiguous data is not confirmation of admission.

## Prevention

- Verify that channel-neutral response formatting exposes relevant typed
  result fields, not only the top-level success message.
- Keep incomplete-data outcomes visibly distinct from positive fit statuses.
- Exercise one complete admission query through the browser and inspect the
  rendered result text, not just the HTTP status.
