# Require funding choice in admission chat

## Problem

Admission search could run after the applicant supplied scores and university
scope while leaving funding unspecified. Where budget and paid offerings differ,
that makes results ambiguous. The response also needs to distinguish user
choices from safe policy defaults.

## Root cause

The query/session flow did not collect funding as a required admission slot,
did not restore enum-valued facts reliably after database JSON hydration, and
had no explicit source-backed rule for choosing an admission year when the
user omitted it.

## Solution

- Ask whether to consider budget or paid study after the required EGE and
  university scope are known; keep an explicitly supplied preference.
- When omitted, select the latest published year matching the chosen funding
  type and full-time study form, and mark both defaults as inferred policy
  parameters in the response. Do not silently substitute the current calendar
  year or turn missing offerings into zero-valued facts.
- Preserve enum facts through query-session persistence/hydration and pass the
  selected year, form, and funding type to the batch Admission Fit gateway.
- Update complete-query fixtures to include funding; fix the browser assertion
  to inspect the complete clarification message rather than assuming each text
  option is a separate DOM node.
- Keep offline Jev evaluation statuses explicit: `not_run_offline` means the
  harness did not call the provider and says nothing about credential presence.

## Prevention

- A complete admission request fixture must state funding; otherwise test the
  funding clarification.
- Keep explicit applicant facts separate from disclosed defaults and recheck
  persisted sessions when enum-valued slots change.
- Exercise the live API and the browser with source-backed result gaps; do not
  equate HTTP success or a readiness score with a guarantee of admission.
- Run the backend from the repository-root configuration context when verifying
  relative Jev calibration artifact paths; never log provider credentials.
