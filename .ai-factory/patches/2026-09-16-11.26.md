# CI strict JSON enum boundary

## Symptom

The clean GitHub Actions runner resolved Pydantic 2.13.5 while the local
environment still used Pydantic 2.10.6. With the project's strict API models,
the analytics endpoint rejected the valid JSON string `eventType` with HTTP
422 because the value was not converted to `AnalyticsEventType` at the HTTP
boundary.

## Root cause

The request schema relied on older Pydantic behavior for strict enum fields.
The public JSON contract contains enum values as strings, so that conversion
must be explicit and deterministic in the API schema rather than delegated to
version-specific coercion.

## Prevention

- Use a `BeforeValidator` for enum fields that receive JSON strings while
  keeping `ApiModel(strict=True, extra="forbid")` enabled.
- Re-run the full backend suite against the newest supported dependency
  versions when a clean CI runner exposes a validation drift.
- Keep replay tests at the HTTP boundary so valid analytics events and strict
  payload rejection remain covered together.
