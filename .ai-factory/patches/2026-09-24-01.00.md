# Preserve observed Jev model identity in typed decisions

## Problem

Successful Jev responses could be accepted by the configured calibration gate,
but the typed decision returned `rule-based.v1` as its `model_version` when the
provider omitted that optional field from the response payload. This made
runtime telemetry and downstream explainability disagree with the model
identity used by the transport and calibration check.

## Root cause

The adapter validated the provider payload into a typed decision whose
`model_version` field has a deterministic default, then copied operation and
source without replacing that default from the trusted transport envelope.
The transport identity is already used for calibration compatibility.

## Solution

- Copy `response.identity.model_version` into each successfully validated
  typed Jev decision; deterministic fallback metadata is unchanged.
- Emit a structured, secret-safe completion log containing provider/model
  identity and request timing, without logging user text or credentials.
- Keep action applicability checks and deterministic clarification wording
  unchanged; Jev does not gain authority over unsupported actions.

## Prevention

- Treat transport-authenticated provider identity as the source of truth for
  model metadata; never allow an omitted payload field to masquerade as a
  deterministic model version.
- Keep one cookie jar when testing multi-turn assistant sessions over HTTP.
- Distinguish local/runtime verification from hosted CI status.
